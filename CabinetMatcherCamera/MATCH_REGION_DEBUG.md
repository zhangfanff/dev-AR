# 1.5 匹配区域排查

本次修改项目为 `G:\AndroidStudioProjects\CabinetMatcherCamera`，应用名仍是“开关柜摄像头”，包名仍为 `com.example.cabinetmatcher.camera`，版本号 7 / `1.5-match-region-debug`。APK 可覆盖安装原摄像头实验版。

## 如何查看

1. 按原来方式选择模型、开启相机、开始识别。
2. 实时预览中的 `K0 → R12` 表示旋钮 K0 实际选择了文字检测区域 R12，箭头连接两者。区域编号仅属于当前处理帧，不是跨帧跟踪身份。
3. 彩色框表示几何配对成功；橙色配对表示 OCR 未通过，包括低置信度、空文本或识别异常。灰色的 `R… 未选中` 是检测到了但没有分配给旋钮的区域，不会执行文字识别。
4. 发现问题后点击“暂停识别”，固定最近完成帧。下方整帧图支持原有的双指放大和拖动。
5. 在“匹配区域原图预览”中逐个查看 K→R：原始画面中的文字区域、实际文字多边形轮廓、OCR 原始输出、置信度状态、距离和相对搜索轴的夹角。没有读取到文字的区域仍然显示；低于识别阈值的原始输出不会被删除。
6. 没有几何配对的旋钮显示总拒绝原因，以及距离最近的至多三个候选区域的拒绝原因。图中灰框的 R 编号可与这些候选对应。
7. 导出该帧 JSON 可查看所有候选、实际选中区域的多边形/坐标、原始 OCR 输出、状态、识别分数、异常信息、占用关系和拒绝原因。导出 PNG 包含所有检测框、K/R 编号、OCR 状态和匹配箭头。

## 两种情况要区分

- **已经选中文本区域，但 OCR 不通过**：有 K→R 连线和原图区域；状态为 `low_confidence`、`empty_text` 或 `error`。
- **没有选中文本区域**：显示“没有几何配对”，没有可展示的已选中区域。原因可能是未检测到文字、方向/距离/扇区不符、文字中心落在当前旋钮框内，或文本已被高优先级旋钮占用。

本版仍先进行几何匹配，再只识别匹配区域。OCR 失败后不换选其他区域。本次没有修改文字检测、匹配规则、文本中心排除条件、识别阈值或推理调度，便于先观察原逻辑到底选中了什么。

## 图像与内存

原图预览直接读取本次分析帧的未标注位图，绘制文字框外接矩形的放大区域及多边形轮廓，不使用被框线和文字覆盖后的标注图。它不是透视矫正后的 OCR 网络输入，纯粹用于查看原始选择位置，也不会重新运行 OCR 或增强图像。

每个保留的完成帧多持有一张原图，未为每个区域复制子图。切换新结果时释放旧原图和标注图，暂停时保留当前结果，销毁和无效会话结果统一回收。

实时预览仍叠加最近完成的旧帧结果，移动相机时会有延迟。排查文字匹配应以暂停后的历史帧和原图区域为准。
