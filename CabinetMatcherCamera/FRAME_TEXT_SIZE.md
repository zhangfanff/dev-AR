# 文字检测跟随相机分析帧尺寸

版本 `1.10-frame-text-size`，versionCode 12。

安装包：`dist/CabinetMatcherCamera-frame-text-size-arm64-debug.apk`。构建和运行验证见 [VALIDATION_FRAME_TEXT_SIZE.md](VALIDATION_FRAME_TEXT_SIZE.md)。

在页面下方“暂停识别后可调整设置”区域，新增“文字检测尺寸”下拉框：

- **手动长边上限（原方式）**：默认选项，继续使用下方手动长边参数，默认 1600，可填写 32～2048。
- **跟随相机分析帧（原尺寸）**：跳过手动长边限制，以实际分析帧宽高进行文字检测。手动长边输入框变灰，其值不参与本次处理。

操作：暂停识别，选择“跟随相机分析帧（原尺寸）”，再开始识别。模式选择即时保存，界面重建和重启后恢复，也可随时暂停后切回手动模式。可以与全部 OCR 选项、单方向/四方向检测组合使用。

跟随的是经过 CameraX 裁剪和相机方向纠正后的**实际分析帧**。采集菜单的“优先 1920×1080”是分辨率请求；设备最终提供的尺寸及 ViewPort 裁剪可能不同。该选项本身不提高相机采集分辨率，也不把低分辨率帧放大成高分辨率。

PP-OCR 和 DBNet 的输入宽高继续对齐到最接近的 32 倍数，沿用原来的取整规则；ML Kit 保留帧宽高（极小图片仍满足最小 32 像素的边长）。例如实际分析帧为 1920×1080：

| 后端 | 手动长边 1600 | 跟随分析帧 |
|---|---|---|
| PP-OCR / DBNet | 1600×896 | 1920×1088 |
| ML Kit（提交给 SDK 的图片） | 1600×900 | 1920×1080 |

四方向中的 90°/270° 使用交换后的宽高。跟随模式没有原手动模式的 2048 长边限制；实际帧超过 2048 时仍按帧尺寸处理。高分辨率、较大模型和四方向组合会增加耗时及内存占用，效果与速度请用同一画面比较。

详细计时现在显示每个方向的“源图宽×高 → 检测输入宽×高”。JSON 新增 `parameters.text_detection_size_mode`（`MANUAL_LIMIT` / `FOLLOW_FRAME`）及每次检测的 `timings.text_detection_passes[].source_image_size` / `detector_input_size`。跟随模式下 `parameters.ocr_det_side` 为 null，实际尺寸以逐次检测记录为准；ML Kit 的输入尺寸指提交给 SDK 的图片，SDK 内部网络预处理不由应用控制。

旋钮检测、坐标映射、匹配和后续从原分析帧裁剪识别继续沿用现有流程。
