# 可选的四方向文字检测

版本 `1.9-four-direction-text`，versionCode 11。

安装包：`dist/CabinetMatcherCamera-four-direction-arm64-debug.apk`。构建和运行验证见 [VALIDATION_FOUR_DIRECTION_TEXT.md](VALIDATION_FOUR_DIRECTION_TEXT.md)。

应用顶部 OCR 模型下方新增“文字检测方向”下拉框：

- **单方向检测（原方式）**：默认选项。只检测原分析帧，保留原检测框顺序及分割，不进行跨方向合并。
- **四方向检测后合并（0° / 90° / 180° / 270°）**：原分析帧及顺时针旋转三个角度的图片分别检测，将全部四角坐标还原到原分析帧，合并跨方向的重复框，再执行原有旋钮匹配和已选区域 OCR。

操作：**暂停识别 → 选择文字检测方向 → 开始识别**。选项会即时保存，界面重建或重新启动后恢复；旧版没有该设置时使用单方向模式。与 OCR 模型选择、旋钮匹配方向、0/180° 文字方向纠正相互独立。

## 实现与计时

旋钮仍只检测一次。四次文字检测串行复用同一套已加载的 OCR，不额外创建四套模型。原分析帧不做原地旋转，旋转副本使用后释放；YOLO / 手部任务仍使用同一原始帧。串行、并行执行模式均可使用该选项。

坐标反变换使用原图宽高和像素边界 `width - 1` / `height - 1`，90°/270° 输入的宽高交换。保留检测四角的环绕次序，供原图透视裁剪使用。旋钮的上/下/左/右搜索始终在原分析帧坐标中判断。

合并按实际凸四边形的 IoU（交并比）进行，阈值 0.5。较大面积框优先，面积相同时保留较早检测方向（0° 优先）；只抑制跨检测方向的重叠框，保留同一次检测本身的分割。最终按原图上边界、左边界排序后分配区域 ID。该方法是几何去重，不使用尚未运行的 OCR 分数；不同方向把同一行分成不同粒度时，仍可能残留碎片框或发生合并差异，需结合匹配区域预览判断。

现有方向分类和识别规则继续生效。四方向检测补充的是候选区域，不保证检测来源角度就是文字正向，也不保证已找到的框一定识别正确。

详细耗时新增输入旋转、坐标还原、跨方向合并及每个角度的耗时/原始框数，显示“累计框数 → 最终区域数”。`ocr_detection.total` 包含全部方向和合并，父合计已经包含子步骤，不要重复相加。

JSON 增加：

- `parameters.text_detection_mode`：`SINGLE` 或 `FOUR_DIRECTIONS`。
- `timings.text_detection_passes`：每次检测的顺时针旋转角度、框数、耗时。
- `timings.raw_text_region_count` / `merged_text_region_count`：合并前后数量。
- `timings.cross_direction_merge`：当前合并规则。
- ML Kit 的 `ocr_engine.whole_image_sdk_calls` 按实际检测次数记录为 1 或 4；选中区域的 SDK 识别次数另计。ML Kit 不提供独立检测接口，因此四方向的整图 SDK 调用同时执行检测和识别，整图字符串仍不参与匹配。

## 对比方法

对同一柜体固定取景、视频尺寸、OCR 模型、OCR 检测长边、匹配方向和识别阈值，分别运行两种检测模式。观察原先缺失的侧转/倒置标签是否出现、区域是否重复、旋钮是否仍配对正确，以及去除首帧后的处理均值。四方向增加检测耗时，也可能增加误检；不能把新增框数直接当成识别准确率提升。模糊、反光、小字或遮挡也不会因旋转自动消失。
